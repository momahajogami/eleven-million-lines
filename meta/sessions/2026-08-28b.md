### Diagnosing the 404

The site had been configured in GitHub Settings → Pages (Branch: main, Folder: /docs) but was returning 404. All "pages-build-deployment" workflow runs showed green — which was the confusing part. The builds were succeeding but nothing was being served.

First attempted fix: added a `.nojekyll` file to `docs/`. GitHub's Jekyll processor can suppress certain files, and `.nojekyll` tells it to skip processing entirely.

```bash
touch docs/.nojekyll
git add docs/.nojekyll
git commit -m "fix: add .nojekyll to disable Jekyll processing for GitHub Pages"
git push origin main
```

Still 404. The `.nojekyll` file was not the root cause.

### The real fix: switching to GitHub Actions

The "deploy from branch" Pages method was silently broken — a known GitHub Pages quirk, especially on newer accounts or repos. The fix was to switch to the explicit GitHub Actions deployment method, which calls GitHub's Pages API directly rather than relying on the branch-watcher.

Steps:
1. In GitHub Settings → Pages, changed Source from "Deploy from a branch" to "GitHub Actions"
2. Created `.github/workflows/pages.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: docs/
      - id: deployment
        uses: actions/deploy-pages@v4
```

What each step does:
- `checkout` — pulls the repo into the GitHub Actions runner (a temporary Ubuntu VM)
- `configure-pages` — sets up the Pages environment on GitHub's side
- `upload-pages-artifact` — packages the `docs/` folder as a deployment artifact
- `deploy-pages` — pushes that artifact to GitHub's CDN and makes it live

The `permissions` block is required: GitHub Actions runners have no permissions by default. `pages: write` and `id-token: write` are specifically needed for Pages deployment.

```bash
git add .github/workflows/pages.yml
git commit -m "ci: add GitHub Actions workflow for Pages deployment"
git push origin main
```

Site went live immediately after the workflow completed.

## Things to learn before next session

- **GitHub Actions in depth**: the workflow YAML format — `on`, `jobs`, `steps`, `uses`, `with`. Each `uses:` line calls a pre-built action from the GitHub Actions marketplace. Actions are versioned (e.g. `actions/checkout@v4`).
- **Why "deploy from branch" broke**: this method relies on GitHub detecting pushes and running an internal build. On some accounts/repos it silently fails. The Actions method is explicit and auditable — you can see every step.
- **Concurrency in workflows**: the `concurrency` block ensures only one Pages deployment runs at a time. If a new push comes in while deploying, it cancels the in-progress run and starts fresh.
