### Unit 10 — Codebases

**Mosaic** (`10/mosaic/src/`) — full clone of alandipert/ncsa-mosaic mirror.
~95,000 lines of C. The `<IMG>` decision is traceable:
- `libhtmlw/HTMLparse.c` line 1378: `<IMG>` becomes `M_IMAGE`
- `libhtmlw/HTMLformat.c` line 2787: `SRC` attribute parsed
- `libhtmlw/HTMLformat.c` line 2827: `SetElement` places image inline

Also fetched:
- `10/mosaic/rfc2616-http.txt` — RFC 2616, HTTP/1.1 (9,859 lines)
- `10/mosaic/rfc1866-html2.txt` — RFC 1866, HTML 2.0 (4,315 lines)

The `<IMG>` definition is in RFC 1866 Section 5.10 with Berners-Lee's
objection still visible in the NOTE: "if a graphic is essential, it
should be referenced from an `<A>` element."

```bash
git clone https://github.com/alandipert/ncsa-mosaic 10/mosaic/src
curl -sL https://www.rfc-editor.org/rfc/rfc2616.txt -o 10/mosaic/rfc2616-http.txt
curl -sL https://www.rfc-editor.org/rfc/rfc1866.txt -o 10/mosaic/rfc1866-html2.txt
```

**Lynx** (`10/lynx/src/`) — fetched as tarball from invisible-island.net,
version 2.9.3. ~109,000 lines of C.

```bash
curl -sL https://invisible-island.net/archives/lynx/tarballs/lynx2.9.3.tar.gz \
  -o /tmp/lynx.tar.gz
tar -xzf /tmp/lynx.tar.gz -C 10/lynx/src --strip-components=1
```

The contrast with Mosaic: `src/HTML.c` line 2938, `case HTML_IMG:` —
Lynx encounters an image, reads the ALT attribute, and moves on.
Same tag, same RFC, completely different response.

**Mastodon** (`10/mastodon/src/`) — blobless sparse checkout.
Models, services, workers, schema.

```bash
git clone --filter=blob:none --no-checkout \
  https://github.com/mastodon/mastodon.git 10/mastodon/src
cd 10/mastodon/src
git sparse-checkout init
git sparse-checkout set app/models/ app/services/ app/workers/ \
  app/lib/ db/schema.rb config/routes.rb
git checkout HEAD
```

Key file: `app/services/fan_out_on_write_service.rb` — 182 lines,
the entire feed algorithm. Three method calls. Chronological.
No engagement ranking. The contrast with Twitter's closed algorithm
is the lesson.

### Website pipeline (second half of session)

#### The problem

Unit pages at `docs/NN/index.html` were static HTML written by hand.
No connection to the markdown living in each unit directory. Every time
unit content changed, the website silently fell behind.

#### The solution: WEBSITE.md + build script

Defined a format for `NN/WEBSITE.md`:
- **Line 1** — tagline (short, punchy; becomes `<p class="tagline">`)
- **Body paragraphs** — description (becomes `.description` div)
- **`## Materials` section** — bulleted list (becomes `.materials` div)

Built `scripts/build-website.py`. Key pattern: regex with `re.DOTALL`
to replace multi-line div contents:

```python
re.sub(
    r'(<div class="description">).*?(</div>)',
    rf'\1\n{content}\n\2',
    html, flags=re.DOTALL
)
```

`re.DOTALL` is essential — without it, `.` doesn't match newlines and
the substitution silently fails on multi-line blocks.

The script also converts markdown inline elements: `**bold**` → `<strong>`,
`` `code` `` → `<code>`, `[text](url)` → `<a href>`.

Run it:
```bash
python3 scripts/build-website.py
```
