Blender's Python API — bpy

Blender exposes almost everything to Python. Every object, mesh, material, modifier, node graph, render setting, and UI panel is accessible and modifiable through bpy. The API is comprehensive enough that a significant portion of Blender's own interface is built with Python: all the operators in the menus, all the panels in the Properties editor, most of the Import/Export formats.

This makes Python in Blender qualitatively different from scripting in most creative applications. You are not writing macros against a limited public API. You are writing Python that runs inside the same process as Blender, with access to the same data structures described in source/blender/makesdna/.

The three namespaces

bpy has three main namespaces:

bpy.data — the scene database. Every datablock in the current .blend file is accessible here. bpy.data.objects is a collection of all objects. bpy.data.meshes is all meshes. bpy.data.materials is all materials. These are the same ID structs from DNA_object_types.h, exposed through Python wrappers generated by the RNA system.

bpy.ops — operators. Every menu item in Blender is an operator. bpy.ops.mesh.primitive_cube_add() adds a cube. bpy.ops.object.delete() deletes selected objects. Operators are context-sensitive — they act on whatever is currently selected, in whatever mode is currently active. This makes them convenient for interactive use and inconvenient for scripts that need precise control. For precise control, manipulate bpy.data directly.

bpy.context — the current state. bpy.context.active_object is the active object. bpy.context.scene is the current scene. This changes as the user interacts with Blender. In scripts run non-interactively (--background mode), context is limited.

Exercise 1: Run hello-blender.py

Open Blender. Go to the Scripting workspace (tab at the top). Open 04/scratch/hello-blender.py in the text editor. Read it before running it. Then run it.

Watch what happens in the 3D viewport. A grid of colored spheres appears. The script built this from Python — the same operations you would perform by hand in the UI, but automated.

Then look at what was created: bpy.data.objects now has 27 entries (25 spheres, 1 light, 1 camera). bpy.data.materials has 25 entries. The Python collections are live views into the .blend data.

Exercise 2: Inspect from the Python console

Open the Python console (available in the Scripting workspace). After running hello-blender.py, try:

# List all object names
[obj.name for obj in bpy.data.objects]

# Get the first sphere
sphere = bpy.data.objects['Sphere']

# Its position
sphere.location

# Move it
sphere.location.z += 5

# Its material
sphere.data.materials[0].name

# Get the material's base color
mat = sphere.data.materials[0]
mat.node_tree.nodes['Principled BSDF'].inputs['Base Color'].default_value[:]

You are traversing the same data structures described in the DNA headers: Object → Mesh → Material → bNodeTree → bNode → bNodeSocket.

Exercise 3: Write a modifier script

Blender's modifiers (Subdivision Surface, Array, Boolean, etc.) are accessible through obj.modifiers. Write a script that:

  1. Selects all sphere objects in the scene
  2. Adds a Subdivision Surface modifier to each with render_levels = 2
  3. Prints the final polygon count of each mesh after subdivision

This exercises the bpy.data approach: no operators, direct manipulation of the data.

import bpy

for obj in bpy.data.objects:
    if obj.type == 'MESH' and 'Sphere' in obj.name:
        mod = obj.modifiers.new(name="Subsurf", type='SUBSURF')
        mod.render_levels = 2
        # depsgraph evaluation to get the subdivided mesh
        dg = bpy.context.evaluated_depsgraph_get()
        eval_obj = obj.evaluated_get(dg)
        eval_mesh = eval_obj.to_mesh()
        print(f"{obj.name}: {len(eval_mesh.polygons)} polygons after subdivision")
        eval_obj.to_mesh_clear()

Notice evaluated_depsgraph_get() — this is the dependency graph from source/blender/depsgraph/ surfaced through Python. You are asking the graph to evaluate the object with all its modifiers applied.

Exercise 4: Non-interactive rendering

Run from the command line:

blender --background --python 04/scratch/hello-blender.py

Blender starts without a UI, runs the script, and exits. This is how studios use Blender in production pipelines: render farms run Blender headlessly with Python scripts that configure scenes and trigger renders.

To render to a file, add to the script:

bpy.context.scene.render.filepath = "/tmp/render.png"
bpy.ops.render.render(write_still=True)
